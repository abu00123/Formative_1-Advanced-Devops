# Contributing to Rwanda Cultural Archives

## Branching

- Branch off `main` for every piece of work
- Name branches: `feature/`, `fix/`, `devops/` followed by a short description
- Example: `feature/search-functionality`, `devops/configure-ci`

## Commit Messages

Use clear, present-tense messages:
- `Add browse page component`
- `Fix search filter bug`
- `Configure branch protection rules`

## Pull Requests

- Every PR needs at least 1 approval before merging
- Link the related GitHub Issue in your PR description
- Resolve all review comments before merging

## Code Style

- Use consistent indentation (2 spaces for JS/JSX)
- Keep components small and focused
- Comment only where the code isn't self-explanatory
